구현한 것

종족마다 다른 수명과 시간

고블린 40년부터 뱀파이어 1000년까지 수명이 다르고, 한 턴은 수명의 80분의 1입니다. 나이 단계도 수명 대비 비율로 나눠 어떤 종족이든 80턴 안팎의 일생이 됩니다.

조건이 붙는 사건

사건마다 나이 단계, 종족, 신분, 결혼 여부 같은 조건과 한 번만, 쿨다운, 최대 3회 규칙을 붙여 매번 다른 이야기가 나오게 했습니다.

이어지는 이야기

가게를 차리면 경쟁 가게가, 빚을 지면 빚 독촉과 상환이 이어지도록 표시(플래그)로 사건을 연결했습니다.

가족과 친구, 같은 날 태어난 이들

부모, 배우자, 자녀, 친구도 함께 나이를 먹고 세상을 떠납니다. 같은 날 다른 종족 4명이 태어나 그들의 소식이 들려옵니다.

직업과 위기

공통·신분·종족 직업 중 하나를 고르면 직업 사건과 직업 위험이 생기고, 사고는 바로 죽지 않고 '위기'로 먼저 나타나 건강이 높을수록 살아남습니다.

점수, 통계, 기록 파일

능력치 평균, 업적, 수명을 채운 정도로 점수를 매기고, 여러 판의 통계와 인생 요약을 파일로 저장합니다. 슬라임은 분열체로 다음 세대를 이어 갑니다.

핵심 코드

/* 사건: 문장과 효과, 조건을 데이터로 분리해 data.c 에 모았다 */
typedef struct {
    char name[30];          /* 짧은 이름 (기록·사망 원인에 사용) */
    char text[120];         /* 화면에 보여 줄 문장 */
    int  race;              /* -1 공통, 0~9 종족 사건 */
    int  stage;             /* 일어나는 나이 단계 */
    int  effect[STAT_COUNT];/* 능력치 변화 */
    int  cond;              /* 일어나기 위한 조건 (enum Cond) */
    int  special;           /* 특별 처리 번호 (enum Special) */

    int  needFlag;          /* 이 표시가 켜져 있어야 일어난다 */
} Event;

디버그 해결 경험

같은 사건이 계속 반복됨

문제
한 사람의 일생에 같은 사건이 연달아, 또는 열 번 넘게 나와 이야기가 단조로웠습니다.
원인
조건에 맞는 사건 중에서 매 턴 무작위로만 골라서, 후보가 적은 단계에서는 같은 사건이 계속 뽑혔습니다.
해결
사건별로 나온 횟수와 마지막 턴을 기록해, 8턴 안에는 다시 나오지 않고 일생에 최대 3번까지만 나오게 했습니다.

컴파일러마다 한글이 깨짐

문제
Visual Studio에서는 한글이 잘 나오는데, gcc로 컴파일하면 콘솔 글자가 깨졌습니다.
원인
gcc는 소스의 한글을 UTF-8 그대로 두고, Windows 콘솔은 기본이 CP949라 서로 맞지 않았습니다.
해결
gcc로 컴파일할 때만 SetConsoleOutputCP(65001)로 콘솔을 UTF-8로 바꾸도록 #if로 나눴습니다.

화면의 숫자와 실제 능력치가 다름

문제
고블린은 재산 변화가 2배인데, 화면에는 원래 숫자가 찍혀 계산이 맞지 않아 보였습니다.
원인
능력치를 바꾸는 addStat()에서만 2배를 하고, 출력하는 쪽은 원래 값을 썼습니다.
해결
출력하는 changeStat()에서도 같은 조건으로 2배를 해서 보이는 숫자와 실제 변화를 맞췄습니다.

엉뚱한 직업이 선택됨

문제
직업 사건이 다른 직업을 가진 사람에게 나오거나, 후계자가 아닌데 후계자 규칙이 적용됐습니다.
원인
직업 번호를 숫자로 직접 적어서, jobs 배열 순서를 바꾸자 번호가 어긋났습니다.
해결
직업 번호를 enum JobId로 이름 붙이고, 배열 순서와 같아야 한다는 주석을 달아 번호 대신 이름으로 쓰게 했습니다.

배운 점과 성취

핵심으로 배운 것

  • 구조체 배열로 게임 데이터(종족, 직업, 사건)와 로직을 분리하는 설계
  • enum으로 숫자에 이름을 붙여 실수를 줄이는 방법
  • 헤더 파일과 extern으로 여러 .c 파일을 나눠 관리하는 법
  • 천분율 확률과 가중치로 게임 밸런스를 조절하는 방법

성취

  • 과제가 아닌 개인 프로젝트로, 세계관부터 밸런스까지 혼자 설계하고 만들었습니다.
  • 사건 170여 개를 데이터로 분리해 숫자만 바꿔도 게임 밸런스를 조절할 수 있게 했습니다.
  • 이 사이트에서 원본과 같은 확률과 문장으로 플레이할 수 있습니다.
