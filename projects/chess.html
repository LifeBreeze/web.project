바로 플레이하기

차례 - 남은 시간 없음

내 말을 누르면 갈 수 있는 칸이 **, 잡을 수 있는 말이 [ ]로 표시되고, 그 칸을 누르면 옮깁니다. 콘솔처럼 오른쪽 입력 칸에 e2(말 고르기 → 도착 칸 입력), e2e4, undo, save, resign, draw를 쳐도 됩니다. 기보는 이 브라우저에 저장됩니다.

추가한 기능

① 색상 체스판

ANSI 트루컬러 코드(\033[48;2;R;G;Bm)로 웹처럼 0xRRGGBB 색을 지정해, 칸은 슬레이트 블루 두 톤, 말은 굵은 흰·검은 글씨로 찍었습니다. Windows 10 이상에서는 콘솔의 가상 터미널 모드를 켜서 같은 색이 나옵니다.

② 이동 가능 칸 표시

e2처럼 칸만 치면 그 말이 갈 수 있는 빈칸은 **, 잡을 수 있는 말은 [ ]로 표시하고, 이어서 도착 칸(e4)을 치면 옮깁니다. 그냥 Enter면 취소합니다. 색이 안 보이는 환경을 위해 글자 표시도 함께 바꿨습니다.

③ 무르기

수를 두기 전의 게임 상태를 배열에 쌓아 두고, undo를 치면 직전 상태로 통째로 되돌립니다.

④ 기보 저장과 다시 보기

둔 수를 e2e4, e7e8q 형식으로 기록해 파일로 저장하고, 메뉴에서 불러와 Enter를 누를 때마다 한 수씩 다시 둡니다.

⑤ 잡은 말과 점수

폰 1, 나이트·비숍 3, 룩 5, 퀸 9점으로 잡은 말의 점수를 더해 누가 몇 점 앞서 있는지 보여 줍니다.

⑥ 제한 시간

1인당 제한 시간을 정하면 생각한 시간만큼 남은 시간에서 빼고, 0이 되면 상대가 이깁니다.

핵심 코드

/* 흩어져 있던 전역 변수를 구조체 하나로 묶었다.
 * 구조체는 = 로 통째로 복사되므로, 백업·복원(무르기)이 한 줄로 끝난다. */
typedef struct {
    Piece board[BOARD_SIZE][BOARD_SIZE];
    Color turn;
    bool  enPassantAvailable;
    int   enPassantX, enPassantY;
    PieceType captured[2][16];
    int   capturedCount[2];
} GameState;

bool isLegalMove(int sx, int sy, int dx, int dy) {
    if (!isValidMove(sx, sy, dx, dy)) return false;
    Color mover = game.board[sx][sy].color;
    GameState backup = game;
    doMove(sx, sy, dx, dy);
    bool ok = !isCheck(mover);
    game = backup;                 /* 구조체 통째로 복원 */
    return ok;
}

디버그 해결 경험

체크를 피한 수를 되돌리면 판이 망가짐

문제
자기 킹이 체크되는 수를 막아 되돌린 뒤, 캐슬링한 룩이나 앙파상으로 잡힌 폰이 제자리로 돌아오지 않았습니다.
원인
원본은 출발 칸과 도착 칸의 말 두 개만 되돌려서, 함께 움직인 룩과 잡힌 폰, hasMoved, 앙파상 기록은 복구되지 않았습니다.
해결
판과 차례, 앙파상 기록을 GameState 구조체 하나로 묶고, 수를 두기 전에 통째로 백업했다가 복원했습니다. 이 구조 덕분에 무르기도 한 줄로 만들 수 있었습니다.

공격받는 칸을 지나는 캐슬링

문제
체크 상태이거나 킹이 지나가는 칸이 공격받고 있어도 캐슬링이 됐습니다.
원인
원본 canCastle()은 사이 칸이 비어 있는지만 확인했습니다.
해결
칸이 공격받는지 확인하는 isSquareAttacked()를 만들어 킹의 자리와 지나가는 칸을 검사했습니다. 킹은 isValidMove() 대신 주변 한 칸만 따로 검사해, 캐슬링 검사와 서로를 계속 부르는 무한 재귀를 막았습니다.

둘 수가 없는데 끝나지 않음

문제
체크는 아니지만 움직일 수 있는 말이 하나도 없을 때 게임이 멈추지 않았습니다.
원인
스테일메이트 판정이 없었습니다.
해결
모든 말의 모든 칸을 검사하는 hasAnyLegalMove()를 만들어, 둘 수가 없으면 체크일 때 체크메이트, 아니면 스테일메이트로 끝냈습니다.

긴 입력에 프로그램이 망가짐

문제
이름이나 수를 길게 입력하면 다른 변수 값이 바뀌거나 프로그램이 멈췄습니다.
원인
scanf("%s")는 버퍼 크기를 모르고 끝까지 써서 메모리를 넘칩니다.
해결
fgets로 크기만큼만 읽고, 다 못 읽은 나머지 글자는 버리는 readLine()을 만들었습니다.

앞으로 간 폰이 사라짐

문제
앙파상이 가능했던 칸으로 폰이 곧게 전진하면 자기 폰이 사라졌습니다.
원인
앙파상 처리에서 대각선 이동인지, 앙파상 기회가 아직 남았는지를 확인하지 않았습니다.
해결
폰이 대각선으로 빈칸에 들어가고 enPassantAvailable이 켜져 있을 때만 옆의 폰을 잡도록 조건을 추가했습니다.
